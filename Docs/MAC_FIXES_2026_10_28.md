# folio(test) 原生界面复测修复 · 2026-10-28

基于 `codex/macos-inline-editing` 的 2.0.5 测试版本。本轮修复已构建并安装到 `/Applications/folio(test).app`，未覆盖正式 Folio。来源文件 SHA-256、构建时间和备份目录记录于包内 `Contents/Resources/FolioTestBuild.json`。

## 修复

- **外部文件冲突**：桌面便签与普通编辑窗共用冲突操作，提供载入磁盘、明确覆盖、保留草稿并关闭。解决操作与保存共用串行队列，操作期间冻结正文和图片插入；清理草稿失败时不推进正文与磁盘版本。冲突期间停止自动保存重试；原生关闭沿用有错误提示的关闭流程。
- **任务撤销**：macOS 编辑菜单和 `Cmd+Z` / `Cmd+Shift+Z` 向当前焦点窗口转发命令。CodeMirror 正文使用自身历史，覆盖阅读时的任务事务；普通输入框继续使用 WebKit 撤销。锁定和组合输入期间拒绝历史写入，阅读态执行历史事务后保持不可编辑。
- **确认退出位置**：原生标题栏启用时，编辑标题输入框与阅读标题使用同一隐藏规则，移除读写切换产生的标题占位差异。短便签的第一行在进入、编辑中和确认退出后均保持原高度，退出后 caret 消失。
- **标题栏主题**：AppKit 顶栏接收当前便签背景与同一套对比度文字色；普通编辑窗使用解析后的主题颜色。关闭原生材质时背景与正文一致，开启时仍保留原有透明材质。

冲突提示已补齐简体中文、繁体中文和英文。Windows 保留原来的菜单路径。

## 2026-10-29 复查补充

仍有一条原生撤销路径尚未修复：刚打开便签，在阅读态直接勾选任务后，`Cmd+Z` 与菜单“撤销”未找到编辑器，勾选不会撤回；点击正文进入编辑后再撤销有效。当前桥接仅依靠焦点记录编辑器，任务点击保持阅读态而不转移焦点。上面的“任务撤销”修复与下方验收只覆盖先进入编辑再撤销的流程，不能扩大为阅读态直接撤销已通过。

此遗漏已在独立测试应用中通过 Computer Use 确认，作为 PR 已知限制披露；真实中文候选、非激活胶囊悬停、多显示器及 Spaces 仍未完整验收。
