## 第一批代码修复

- 内部正文改为同目录临时写入、fsync、原子替换，失败清理临时文件并保留原文；主窗、便签与胶囊待办提交加载时的更新时间，拒绝旧版本覆盖。跨平台分类操作进入同一写锁，分类路径不能越出笔记目录。
- 便签保存排队，避免新便签多次创建；复制不再清除未保存状态。主窗后台刷新保留保存失败的草稿；关闭便签先完成保存，失败留窗。
- Mac 显式退出由独立生命周期模块等待内部和外部文档窗口保存，失败/超时取消退出；不把胶囊装饰窗当作编辑器等待。
- 外部 Markdown 保留既有 revision 检查、BOM/CRLF 与绑定身份；原子替换保留文件权限位。文件缺失不会以空内容或新文件补写；较旧保存完成不能清除较新的本地草稿。显式“载入磁盘”仅清除对应草稿内容。
- 外部文件刷新在保存进行中保留编辑器；旧的无绑定文本入口也改为原子保存和内容版本检查。覆盖冲突的异步回调不能更新已切换到其他文件的窗口状态。
- 文件监听队列限制为 256，溢出触发重新核对；忽略读取事件、按内容 revision 去重；目录替换/重新出现后重挂监听，避免递归监听被单文件绑定降级。仍需真实同步盘断连/恢复验收。
- 正式小组件使用 `folio` 链接；旧 App Intent 必须匹配原快照，不能仅凭相同行文本重定位。Rust 和 Swift 围栏匹配标记与长度；拒绝快照外的行，撤销共享与写回使用同一顺序边界。
- 原生材质在主线程调用时直接执行，避免投递到主线程后阻塞等待自身。屏幕变化改用 AppKit 通知，移除两秒后台查询；已暂停的折射视图不再请求屏幕采集。

## 2.0.0 构建候选与测量

版本元数据进入 2.0.0，正在构建候选；版本号不表示安装/长期验收已完成。

内部笔记读写、外部草稿写入移到阻塞工作线程，文件锁与 fsync 不再放在同步 IPC 回调里。跨平台共用笔记存储锁；AppKit、WidgetKit 和 Mac 退出协调仍保留独立模块与 cfg。关闭被保存失败取消时不提前把会话标成隐藏；完成保存后的窗口回收直接销毁，避免再次触发关闭保存循环。

不同窗口抢占同一外部草稿槽时，原草稿保存在配置目录 `linked-drafts/<绑定ID>.<窗口哈希>.recovery.json`，不写回外部原文件。该备份保留正文、原 revision 与窗口标识；恢复时先复制其正文到单独文件核对，再决定合并，不能直接覆盖现有 Markdown。此路径目前没有专门的恢复列表界面。

小组件微基准：同一 M4/16 GB、macOS 26.7.1、Swift 6.3.3、`swiftc -O`，32 张虚构便签、相同 4000 字符正文与 300×270 分页；每次进程中快照读取 500 次、热分页 50 次，三个进程取中位数。首次分页是进程布局冷缓存，**不是应用冷启动**。复现：`python3 scripts/benchmark-macos-widgets.py --baseline aab1a79`。

| 微基准，ms/次     | 1.8.9 基线 |  加固后 |
| ----------------- | ---------: | ------: |
| 快照读取/缓存检查 |    0.03350 | 0.03369 |
| 首次分页          |      57.32 |   59.40 |
| 缓存分页          |    0.02096 | 0.02078 |

渲染输出相同，结果没有证明速度提升；首次分页略慢，三个样本不能用于显著性判断。原始结果在 [measurements](measurements/macos-2.0-widget-microbenchmark.json)。测量不接触真实笔记、不启动应用界面。

实际空闲、长文编辑、多便签/胶囊、材质切换、小组件分页/待办的持续 CPU、RSS、GPU 和能耗仍**未测**，按用户要求推迟动态场景。不能用微基准代替这些验收。

效果成本按代码预算区分：关闭原生材质不创建玻璃/折射层；磨砂和轻量玻璃由 AppKit 合成，不启动 ScreenCaptureKit；桌面折射使用屏幕采集和 Metal。普通档便签/胶囊采集上限 12/24 fps，节能档 6/12 fps，便签渲染长边预算从 768 降到 512；改变强度不等于关闭采集。隐藏/暂停窗口从采集需求中剔除，睡眠通知停止采集，唤醒重建。折射视图存在时仍有一秒可见性巡检，最后视图移除后撤销定时器和观察者；实际 GPU/能耗需实机测量。
