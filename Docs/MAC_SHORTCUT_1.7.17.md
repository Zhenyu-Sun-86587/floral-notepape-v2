# Mac 快捷键录制卡死修复 — 1.7.17

2026-10-02，基于 1.7.16。范围是“当前便签”与应用设置中的快捷键录制、检测、保存。

## 诊断

用户录入组合键后界面卡死。本机对卡住的已安装进程采样，主线程停在 `stop_shortcut_recording → install_global_shortcut_bindings → unregister_all → Mutex::lock`；后台注册路径等主线程执行原生快捷键操作。原逻辑录制结束会同时发送 stop 和 surface_session_save，前者为同步 IPC 命令，后者在工作线程执行，构成锁与主线程调度的循环等待。这是死锁证据，不是仅凭界面截图判断崩溃。

## 修复

- 开始/结束录制、快捷键检测和配置保存改为 async IPC 命令，阻塞操作进入 spawn_blocking，主线程只执行必要的原生动作。删除便签后的快捷键刷新也进入后台。
- 后台快捷键检测、暂停和注册事务串行，避免恢复与保存同时改动注册表。
- 不使用持插件锁等待主线程的 unregister_all，改用 unregister_multiple 移除应用管理的已注册绑定；失败时清除本次部分注册并恢复旧绑定。
- 录制器结束先等待原生 start/stop 生命周期完成，随后提交 onRecord。同步单次完成标记避免 DOM/系统钩子或重复按键触发多次保存。取消和卸载共用一次 stop，新录制等待旧录制清理。
- Mac Option+字母可能产生 Dead/重音 Unicode，组合键按 KeyboardEvent.code 的物理字母、数字和标点键归一化。IM 输入中及按键重复不提交组合键。失败信息在当前便签入口显示。

## 基础检查

8 项快捷键定向前端测试通过，包含原生 start 尚未完成时取消、stop 完成前不保存、重复组合只提交一次及 Option Dead 键归一化；lint、TS/Vite、cargo check 与 arm64 app/dmg 构建通过。

使用隔离数据目录的临时测试笔记在真实 Mac 界面检查：录制 Command+Shift+F9、Esc 取消、清除均保持响应，不改动用户便签绑定。最终版本复测 Command+Option+N 的归一化、保存到配置文件、Esc 保留原绑定与清除，均通过。临时测试进程已关闭，用户原有笔记及快捷键未改动。

## 人工复测

1. 在截图中的“启动 → 全局快捷键”录制自己的组合键，检查保存后界面响应、菜单可关闭。
2. 连续重录数次，Esc 取消、清除、恢复默认；已有快捷键应按状态恢复，取消不修改绑定。
3. 在应用设置中的快捷键入口录制并检测冲突。系统保留组合可能由 macOS 先处理，换未占用组合测试。
4. 退出重开，检查绑定持久化；触发快捷键展开/收回便签，确认其他已有绑定仍可用。
